# 外部项目主页薄契约

> 这套契约只服务机器读取。它不规定详细设计正文的标题、章节、顺序、篇幅、文风或思考过程，也不把正文复制进 Infans_Vault。

新项目先按 [[90_使用说明/10_规则手册/事业项目轻量启动协议|事业项目轻量启动协议]] 完成事业注册、管理原件和关系网接入。只有确实需要项目主页、工作线、功能树或安全原件入口时，才追加本契约；Project Hub 不是立项门槛。

## 项目侧最小文件

每个获白名单授权的项目只需提供：

1. `.infans/project-hub.v1.json`：项目主页、工作线、功能树关系和安全原件入口的独立清单。
2. 清单引用的原件：仍放在项目自己的目录中，正文结构完全自由。
3. 项目自己的验证命令：至少用本目录的 `infans-project-hub.v1.schema.json` 校验 JSON 结构，再用梅凝共享解析器验证跨 ID 引用与安全路径。

没有功能树的项目可以不写 `featureTrees`。普通工作线不必写 `view`；只有需要进入功能树时，才登记 `view.kind = "featureTree"` 和 `treeId`。

## 薄契约约束什么

- 稳定项目、工作线、功能树、模块和功能 ID。
- 这些对象之间的明确关系。
- 机器状态、展示模式隐藏标记和项目默认入口。
- 项目根内的原件相对引用。
- 为旧版项目保留的任务与近期完成 ID 兼容关联。
- 契约版本和服务器只读安全边界。

任务、阻塞和近期完成正文及正式关系仍写在 Vault 项目 `项目进度与待办.md`；清单中的 `taskLinks` / `recentLinks` 只做 v1 兼容输入，不复制正文，也不再作为新增关系的首选写入点。工作台把项目原件关系与这些兼容链接合并为派生视图。同一条记录可关联多个任务、工作线、模块和功能。

## 不约束什么

- 设计文档用几个标题、采用什么章节顺序。
- 每一章写多长、采用什么文风。
- 讨论过程、推理过程和创作方法。
- AI 如何组织详细设计内容。

解析器不会扫描任意 Markdown 标题来猜项目结构。验证器只判断接口一致性、引用有效性和安全，不评价写作质量。

## 安全边界

共享服务器只按项目 ID 命中代码内明确登记的外部根，前端不能提交路径。清单文件名固定为 `.infans/project-hub.v1.json`。原件只允许项目根内的 Markdown、JSON 或 YAML 相对路径；绝对路径、`..`、反斜杠、符号链接逃逸、凭据、环境文件、`.git`、构建缓存、日志和白名单外文件会被拒绝。

外部根、清单或某个原件不可用时，只降低对应项目或入口，不影响工作台其它页面。
