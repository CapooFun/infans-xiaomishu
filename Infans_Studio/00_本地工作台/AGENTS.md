## 工作台常驻硬边界

1. **原件与写回**：Vault 所属内容原件仍是事实源；工作台只保存代码、策展、明确的本机运行状态和派生结果。持久写入只能走项目设计第 5.2 节的白名单与专用入口，并按实际契约执行来源／稳定 ID／预期状态校验、冲突复查、原子写入和回读；不为方便另开旁路。
2. **私有访问**：不按 Mac、iPad、iPhone、User-Agent 或屏宽放宽权限。本机、Tailscale 与凭据边界以项目设计第 5、7 节为准；空白名单、撤权或身份不明时失败关闭。完整凭据不进源码、文档、聊天、截图或日志。
3. **唯一实现**：Vault 路径只经 `app/src/server/vault-paths.mjs`（前端同步 `src/vault-paths.ts`）；服务端路由只在 `app/src/server/workbench-routes.mjs` 实现，生产服务和 Vite 开发薄壳共用；分区 key 只在 `src/types.ts` 的 `SECTION_DATA_KEYS` 维护。
4. **派生状态**：`home-pins`、`gantt-hidden`、收藏、歌单、聊天、附件和来件等忽略 Git 的数据不等于可丢缓存；只由专用接口原子写入并纳入规定镜像。普通 GET 不迁移、不清理、不落盘。
5. **功能归属**：新功能先在 [[小秘书_产品功能树]] 定位唯一模块原件，再登记稳定功能 ID。功能状态、详细设计、任务和证据各回自己的原件，不在入口文件复制。
6. **平台与自动化**：当前模型、adapter、定时时刻和登录状态从岗位绑定、专项原件和实际运行回执读取，不在常驻入口写死。`AI·`、日期、执行器或平台名都不能单独冒充自动授权或完成。

## 施工与收工

1. 实际改代码、数据、内容或正式工程原件前，先在小秘书项目 `项目进度与待办.md` 登记或复用一个稳定任务 ID；同一目标跨窗口、返工或换 Agent 继续沿用，不重复建票。纯讨论、调查、诊断和只读审查不登记施工任务。
2. 写入前重读目标和当前差异，保留其它窗口的并行修改；不为整洁回退、删除或卷入未知变更。
3. 改 `app/` 代码时，在 `00_本地工作台/app/` 下按影响运行聚焦测试、`pnpm check`、`pnpm build` 和 `git diff --check`。影响正式服务或使用者需要看结果时，默认在同目录运行 `bash scripts/start-local.sh` 并回读 `/api/health`；这是已授权施工的本地收口，无需再次询问，不扩展到 NAS、云端或外部部署。只改 Markdown 或规则不重启。日常正式运行是 build 产物，不用 dev server 冒充。
4. 界面普通检查覆盖桌面和窄屏；高频、触控、全屏或跨端交互再按专项规则检查 iPad 横竖屏、iPhone 与安全区。浏览器尺寸、模拟器、编译或安装不冒充实体设备和使用者本人验收。
5. 版本判断只按 [[小秘书版本治理]]；指定单写者以外的 Agent 不自行升版。有版本候选时，在更新日志留一行：`版本交接：ID=稳定任务ID｜状态=…｜运行=…｜建议=minor/patch/none｜任务=…｜证据=…｜遗留=…`，随后运行 `pnpm version:handoff-check -- --task <本次稳定ID>`，修正本次字段错误；单任务施工可用 `INFANS_VERSION_TASK_ID=<本次稳定ID> pnpm check` 只校验本次交接；未指定 ID 时检查相对 Git HEAD 新增／修改的交接。状态与运行各只填一个合法值，解释放证据／遗留。版本号与 Git 分开；未经授权不 commit、push 或 tag。
6. 有实际推进时，先更新工程或内容事实，再把项目任务收成人能看懂的短结论与证据。只在有长期价值时向更新日志追加可感知变化、决策或踩坑，不把每次小修改写成长报告。
7. 施工任务改了功能或模块原件时，收工前用当前根任务 ID 回读相关功能的「工作上下文」。自动归属遗漏、广泛任务被拆散或使用者明确要求同步时，才用现有核实关联写入派生状态，不凭标题猜归属。
