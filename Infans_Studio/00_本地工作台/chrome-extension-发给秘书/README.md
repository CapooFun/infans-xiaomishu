# 一键发给秘书 · Chrome 扩展

这是一个不上架、只在使用者自己的 Mac Chrome 本地加载的 Manifest V3 扩展。它把本人主动分享的网页、链接、选中文字或公开图片网址送进本机工作台收件箱。现行交互只有“一键发送”，没有备注窗或二级菜单。

## 本地加载

1. 先确认小秘书本机服务已启动。默认健康地址是 `http://127.0.0.1:5173/api/health`；若改了 `INFANS_PORT`，在扩展选项里填同一端口。
2. 在日常 Mac Chrome 打开 `chrome://extensions`。
3. 打开右上角「开发者模式」，点「加载已解压的扩展程序」。
4. 选择本目录：`00_本地工作台/chrome-extension-发给秘书/`。
5. 把「一键发给秘书」固定到工具栏。

Chrome 扩展的真实加载与工具栏位置属于使用者本人验收；源码检查不代替这一步。

## 首次配对

1. 在终端进入 `00_本地工作台/app/`，按仓库说明复制本机设备令牌。
2. 右键 Chrome 工具栏的扩展图标，打开「选项」。
3. Chrome 142 及以后会为 `127.0.0.1` 弹出「本地网络访问」提示；选择允许，直到选项页显示「本机通道已允许」。这项浏览器许可必须在可见页面由本人确认，后台 Service Worker 不能代点或自行弹出。
4. 把整行 `INFANS_CODEX_COMMAND_TOKEN=...` 直接粘贴到「设备令牌」，保存；扩展会自动识别前缀并立即补送已有队列。

安全边界：

- 令牌只写入 `chrome.storage.local`，扩展不使用 `chrome.storage.sync`；
- 令牌不进 manifest、源码、仓库正文、Git、测试、日志或回执列表；
- 扩展唯一主机权限是 `http://127.0.0.1/*`（仅回环，端口可在选项里对齐 INFANS_PORT），没有浏览历史、全网页面监听、内容脚本或同步存储权限。

## 一键使用

- 点一次工具栏图标：当前 HTTP／HTTPS 网页立即写入本地可靠队列；
- 网页右键只有一个「发给秘书」：点在普通页面、链接、选中文字或图片上时，扩展自动识别当前内容并直接发送；
- 图片第一版只发送右键获取的公开 HTTP／HTTPS URL；`data:`、`blob:`、本地文件和图片字节都不会上传。
- 只有收到同一来件的 `mac_persisted` 回执后，当前普通网页顶部才会短暂出现「小秘书已收到」；1.1.5 使用 128px 头像资源显示 82px 外伸头像，文字卡从头像右侧接出且两端圆角一致。Chrome 内部页、PDF 或已离开的标签无法显示页内提示，工具栏绿色勾仍保留真实回执。
- 本机权限、服务或网络失败时，当前普通网页会显示「还没送达」，来件仍留在可靠队列；扩展会打开选项页显示本机通道状态，不再静默失败。

## 回执与恢复

- 首次入队会生成一个 UUID；网络失败、服务未启或令牌错误时，保留原文和原 ID，指数退避重试；
- 工具栏金色数字或「配」只表示本地待送达，不是送达成功；
- 只有严格收到同一 `intakeId` 的 `status: delivered` 和 `deliveryBoundary: mac_persisted` 后，工具栏才短暂显示绿色勾，网页才显示「小秘书已收到」；
- 打开扩展「选项」可看待送达数、失败待重试数和最近的 Mac 持久化回执，也可手动「现在重试」。
- Chrome 142 起，本地网络请求受独立许可保护；可见选项页先完成回环健康探测和授权，再让后台 Service Worker 补送队列。仅重新粘贴令牌不能代替 Chrome 权限，队列为零也不能冒充曾经送达。

## 本人验收清单

- 工具栏点击后，当前网页在小秘书「实用工具 → 收件箱」出现，并在当前页看到「小秘书已收到」；
- 右键菜单只有一个「发给秘书」，没有备注窗和二级菜单；
- 分别在普通网页、链接、选中文字和公开图片上点一次，扩展自动选对内容类型且没有串位；
- 暂停小秘书服务时发一件，扩展只显示待送达；服务恢复后用原 ID 送达，没有因重试生成多份。
